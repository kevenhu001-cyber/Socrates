# 移动端 UI 参考图对齐

## 参考图如何换算

用户提供五张 1200×2670 截图，覆盖首页、抽屉、会话菜单、插件、资料库。顶部约 306px 是 Android 状态栏和 Chrome 工具栏，不属于网页。以 390px CSS 宽度折算，页面约为 390×769；不能把截图中的物理像素直接写成 CSS 像素。

参考图最重要的不是 ChatGPT 商标，而是以下视觉秩序：

- 画布几乎不承载装饰，主要交互集中在顶栏、左侧抽屉与底部输入框。
- 单行问候语位于内容区上中部，留白远大于内容；首页不排列功能卡片。
- 深色输入框是两层结构：上层文字，下层加号、麦克风与主动作。圆角约 28px，控件约 36px。
- 抽屉占屏宽约 65%，导航、历史标题和尾部省略号使用稳定的列对齐；账户区固定在底部，历史列表独立滚动。
- 插件用「应用图标 + 名称/描述 + 操作」的无边框列表，而不是每项一张卡片。
- 资料库用细分隔线建立行节奏，用类型图标建立扫读锚点。文件名优先，修改时间次要。
- 会话菜单必须浮在抽屉之外、限制在视口内，并保持删除动作的危险色。

## 差距与本轮实现

| 表面 | 当前差距 | 本轮调整 |
| --- | --- | --- |
| 首页 | 快捷入口与学习模式入口挤占移动端空白 | 手机聊天首页隐藏两组额外入口；加号菜单和辅导模式的入口仍保留，桌面不变 |
| 输入框 | RN 组件使用独立 card/fill 映射，手机顶内边距偏大、角偏方 | 手机 card/fill 映射到现有 composer/control 语义色；共享 compact frame 顶内边距从 12 收至 8px、圆角从 24 改为 28px |
| 抽屉 | 手机覆盖为 48px 行高，标题 16px；图片、项目顺序漂移；账户与分组都被强制提亮 | 恢复 40px 行距、14px 历史标题与 16px 左侧内容锚线；统一顺序；仅保留品牌图形；取消选中项抬升阴影；恢复次级文字层级；修复关闭搜索后仍占 46px 空间的问题；移除兼容层强制背景 |
| 会话菜单 | 固定 158px 对英文与放大字号不够；圆角退回 16px | 158px 为下限，按内容扩展并限制视口；20px 圆角；不改动作语义 |
| 资料库 | New 为次级灰按钮，列表视图选中态缺少明确圆形底；窄屏搜索余量不足 | 使用黑白反转的主按钮；补充圆形选中态、去掉分类页签整体底板；320px 收紧工具栏间距、不删功能、不缩字号；补充菜单展开状态 |
| 插件 | 已有 36px 搜索、40px 图标与页签、无边框行 | 保持现有参考密度，与资料库一起验收，不重写目录或连接逻辑 |

导航顺序为：新聊天 → 图片（按账户可见性）→ 资料库 → 定时任务 → 插件 → 项目 → 更多。实际账户能力规则保持不变。

手机顶栏另外改为参考图的两笔菜单图标，并以工作区状态隐藏聊天模型入口；手机问候语使用常规字重，避免视觉重心过重。

## 配色与层级

所有活动配色仍由 `frontend/src/styles/themes.css` 管理。本轮不引入另一套 hex 色，也不在兼容 CSS 中新增调色板。

| 角色 | 深色模式基准 | 使用原则 |
| --- | --- | --- |
| 画布 | 现有 `--background` / #0a0a0a | 保留四级背景阶梯约束，不改为参考图的纯黑 |
| 抽屉选中行 | `--ui-bg-panel` / #1f1f1f | 低对比实底，不使用白卡片阴影 |
| 输入框、浮层 | `--ui-bg-composer`、`--popover` / #292929 | 输入表面与临时浮层比画布更亮 |
| 输入控件 | `--ui-bg-control` / #2e2e2e | 控件略高于输入框，保持相邻层级 |
| 主文字 | `--foreground` / #ededed | 导航、文件名、当前可执行动作 |
| 次级文字 | 现有 secondary / tertiary tokens | 分组、账户方案、时间、描述，不与主标题争抢 |
| 主动作 | `--primary` / `--primary-foreground` | 暗色白底黑字，亮色反转；不增加品牌彩色强调 |

浅色和其他主题沿用同一语义映射。品牌资源、favicon、主题注册与 CSP 不变。

## UX 边界

- 不伪造 Plus 订阅、安装应用、账户名或参考图历史记录。
- 不用实时语音图标冒充发送按钮：现有麦克风仍为浏览器语音输入，发送/停止保持真实状态。
- 不把手机密度套到桌面；桌面快捷入口、共享组件非 compact 形态不变。
- 本轮 compact frame 空白态为约 86px，而非原参考合同的 85px：由 8px 顶内边距 + 26px 编辑器 + 8px 间距 + 36px 控件 + 8px 底内边距组成。接受这 1px 的节奏差，不通过裁剪编辑器凑整数。
- 增大字号、附件或多行输入时允许输入框增长；菜单按内容扩宽，长文件名省略，页面不可横向溢出。
- 手机资料库标题继续与插件标题同一基线、位于共享顶栏下方，遵守项目后续确定的目录一致性约定，不把标题硬塞回顶栏。

## 验证范围

新增 `frontend/e2e/mobile-reference-alignment.spec.mjs`，覆盖深/浅色首页、共享输入框实际绘制节点、抽屉密度/导航顺序、会话菜单、插件搜索与资料库选中态，保存截图到 `test-results/`。同时覆盖 320px 和桌面恢复，避免只验证 390px 的静态截图。

旧文档与旧测试中直接检查 `#composerInputWrap` 背景、85px 高度的断言对应 RN 迁移前结构；现在真正的绘制节点是 `[data-composer-frame]`。本轮新增测试直接检查绘制节点，不以透明宿主推断可见颜色。
