# 会话提示词只初始化一次与缓存前缀（2026-10-23）

## 用户要求与语义

会话首次调用时注入提示词，后续只复用第一次确定的内容，尽可能维持高缓存命中率。

这里的“一次”是**初始化一次、持久化一份、后续复用同一份字节**。当前上游使用无状态 Chat Completions，后续请求仍须携带该 system 上下文；不能把提示词从第二个请求中删除并假设供应商会按我们的 sessionId 记住它。

## 实现

- `server/src/services/core/sessionPromptSnapshot.ts`：按当前 owner + session 读取快照；只有不存在时才运行初始化函数。同进程合并并发初始化；不同进程依赖数据库唯一键和 insert-if-absent 选择同一份持久化结果。失败不保留进行中的 Promise，后续可以重试。
- `server/src/db/schema/chat.ts` / 迁移 `0046_session_prompt_snapshots.sql`：独立、服务端专用的 `session_prompt_snapshots` 表。会话为主键；删除会话或用户时级联删除。与 session wire metadata 分离，客户端 PUT、普通详情、分享和跨用户导入不读写这份可信快照。
- `server/src/routes/chat/helpers.ts`：首次组装服务端策略、前端模式/语气/模板/自定义指令、项目背景、用户信息、助手配置及记忆。后续加载已存文本，不重新读取和注入这些设置。
- `server/src/routes/minimaxProxy.ts`：旧版内置模型/非流式入口共用同一份会话快照；在 `/chat` 与内置代理间切换不会重新注入或覆盖原有身份提示词。
- `server/src/lib/chatPolicy.ts`：会话快照以公共服务端策略开头，将个性化信息放在后面。时间标记改为“上下文初始化时间”，不把几天前的时间误称为当前时间。独立的非会话调用保留原有实时上下文行为。
- `server/src/lib/chatPromptContext.ts`：将教学阶段、题目进度、检索证据与滚动摘要从会话级设定中分离。它们属于本轮/历史上下文，不重写固定 system 前缀；检索与摘要保持不可信数据边界。
- `server/src/routes/chat/pipeline/runChatStreamPipeline.ts`：工具名及定义按名称稳定排序；大段工具路由说明和代码运行说明排在动态工具预算之前。预算变化不再使其后面的大段说明同时失去前缀复用机会。

### 行为边界

1. **同一会话**：日期改变、页面刷新、服务重启、用户显示名/记忆/自定义指令/助手配置变化，不会自动生成新快照。设置变化对新会话生效；需要新设定时创建新会话。
2. **旧会话**：未预先写入任何提示词，发布后的下一次聊天懒初始化一次。无法还原过去某日实际发出的完整提示词，因此不声称恢复了“历史首轮原文”。
3. **无 sessionId 的辅助请求**：例如标题生成，保持独立、无状态，不会创建一个全局共享的快照，也不会污染用户会话。
4. **跨用户**：即使已有快照，每次仍验证当前会话归属；无法读取或初始化其他用户的会话。body/query 的 sessionId 同时出现时必须一致。
5. **动态能力**：工具被撤回、权限和额度变化仍逐次生效。不能为了让缓存看起来稳定而向模型承诺已不存在的工具。工具清单真实变化、上下文压缩或配置供应商/model 变化，仍可能影响缓存。
6. **并发**：一个进程内初始化仅执行一次；跨进程初始竞争可能各自计算候选文本，但只持久化一个 winner，所有请求最终使用相同内容。不宣称分布式情况下初始化函数具有 exactly-once 副作用语义。
7. **系统策略更新**：已有会话的基础文本也被冻结。若必须强制更新旧会话的安全策略，需要独立、显式的快照失效/迁移方案；本次未加入任何客户端可调用的清空或覆盖快照入口。权限及工具执行的服务端安全检查不依赖冻结文本。

## 缓存收益的边界

本改动保证会话基础 system 文本不再因每轮注入时间/记忆/设置而变化，固定政策位于个性化信息前，动态预算尽量靠后。

未调用真实付费模型，也没有实测供应商缓存百分比。命中率还依赖供应商缓存最小长度、有效期、模型/Key/用户隔离、工具 schema、完整历史字节是否一致等条件。每轮检索/教学状态仍是动态内容，其在历史中的保存方式可能限制超出 system 前缀之后的复用，不能宣称“全历史 100% 缓存”。

## 发布及回滚

- 必须先通过正常 Drizzle migrator 应用 `0046_session_prompt_snapshots.sql`；SQL 可重复执行，部署 schema 门禁已要求新表存在。当前工作树还包含前一轮待发布的 0045 修复，正常 migrator 应按 journal 顺序处理，不要跳号或伪造账本。
- 按现有单写者部署流程发布，不能覆盖服务正在使用的 live dist。生产迁移/发布尚未在本轮执行。
- 代码回滚可以保留此附加表；旧代码不使用它。**旧代码会恢复每轮重新组装提示词的行为。** 不建议删表或批量清空快照，这会使后续请求重新初始化并损失已稳定的上下文。
- 该表保存会话设定和首次记忆副本，应纳入数据库备份与用户删除策略；用户删除通过外键级联覆盖。删掉某条长期记忆不会改写既有会话快照，与聊天历史中已出现的事实一样，若需彻底移除此会话上下文需删除对应会话。
