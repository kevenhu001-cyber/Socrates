## 已实现且验证通过

- **编辑作用域**：`edit` 按钮仅在 `role==="user"` 消息的工具栏出现（`buildMessageToolbar` L4419-4438），assistant 消息不提供编辑。符合产品预期。
- **流式进行中编辑（无竞态）**：`editUserMessage` 提交前先 `window._activeChatCtl.abort()` 与 `window._activeChatAbort("msg-edit")`（main.js L4571-4572），随后 `askChatTurn` 自身在入口再次 abort（L3403-3404）。双重保护，旧流不会与新回合竞争。
- **上下文重建**：`askChatTurn` 用 `extractHistory()` 从 `state.messages` 重建历史，并在 L3513-3515 切掉末尾重复的 user 回合（避免用户消息被发两次）。编辑后 `state.messages` 已被 `rollbackMessagesAfter` 裁剪到编辑回合，历史正确。

## Bug 票

### BUG-P01-01 — 复制回退路径引用未定义变量 `el`（低，✅ 本次已修）

- **位置**：`main.js` `buildMessageToolbar` → `stripHtmlToText`，原 L4386。
- **现象**：块级元素补换行的循环里写成 `el.appendChild(...)`，但作用域内并无 `el`（循环变量是 `blocks[j]`）。抛 `ReferenceError`，被外层 `try/catch` 吞掉并跌落到正则去标签兜底，导致"从 HTML 复制"时段落 / 列表换行丢失（`<p>a</p><p>b</p>` 复制为 `ab`）。
- **触发条件**：仅当 `entry.rawText` 为空、走 `entry.html` 兜底时（老 payload、服务端未回填 rawText 的消息）。
- **修复**：改为 `blocks[j].appendChild(d.createTextNode("\n"))`。已于本次提交修正。

### BUG-P01-02 — 重生成在服务端留下孤儿旧回答（高，✅ 本次已修）

- **位置**：`regenerateAssistantMessage`（main.js L4628-4649）。
- **根因**：重生成仅在本地 `state.messages.splice` 掉旧 assistant 气泡并重新 `askChatTurn`，**未调用任何服务端删除 / 重生成端点**。收尾的 `saveCurrentSession`（L3563）走全量 upsert：服务端 `sessions.js` L316-330 用 `onConflictDoUpdate` 按 `(sessionId, clientId)` **插入或更新**，但**从不删除** payload 中缺席的行。
- **现象**：旧 assistant（clientId=A）从 payload 消失但服务端行仍在；新 assistant（clientId=B）被插入。**硬刷新后旧回答复活**，与新回答并存 / 错序（排序按 `createdAt`，旧行保留原始时间戳）。
- **对照**：编辑路径通过 `PATCH /api/messages/<id>?...&discardFollowing=true` 删除后续行（L4555-4558）；重生成缺少等价删除。
- **建议修复**：重生成时对被替换的 assistant 消息调用删除（复用 `DELETE /api/messages/<id>` 或新增 `POST /api/messages/<id>/regenerate` 端点，见 `docs/api/openapi.yaml`），再 `askChatTurn`。
- **修复（本次）**：`regenerateAssistantMessage` 改为 `rollbackMessagesAfter(userMessageId)` 回退到 user 回合，并复用编辑路径的 `PATCH /api/messages/<userId>`（`discardFollowing:true, regenerate:false`）删除服务端后续 assistant 行，再 `askChatTurn`。与编辑同源，硬刷新不再复活旧回答（同 BUG-P01-04 一并修复）。

### BUG-P01-03 — 编辑带附件的消息会丢失附件（中，✅ 本次已修）

- **位置**：`editUserMessage.commit`（main.js L4530-4579）配合 `askChatTurn`。
- **根因**：`editUserMessage` 不设置 `window._pendingChatContent`；上一次发送后它已被清空为 `null`（L7456 / L7598）。于是 `askChatTurn` 中 `userContent` 回退为纯文本 `userMsg`（L3440-3442）。虽然 `extractHistory` 会为带附件的 user 回合正确重建多模态 parts（history.js L75-97），但 `askChatTurn` L3513-3515 又把末尾这条 user 历史切掉，改用纯文本 `userContent` 推入（L3534）——**重建出来的图片/PDF parts 被丢弃**。
- **现象**：编辑一条曾带图片/PDF 的用户消息并重发后，模型在该回合看不到原附件（仅纯文本）。
- **建议修复**：`editUserMessage` 提交时若 `entry.attachments` 存在，按 history.js 同一逻辑重建多模态 parts 并写入 `window._pendingChatContent`，使编辑重发携带附件。
- **修复（本次）**：新增导出 `buildUserContentParts(rawText, attachments)`（history.js），编辑提交与重生成前均据此重建多模态 parts 写入 `window._pendingChatContent`（纯文本回合返回 `null`，回退纯文本）。

### BUG-P01-04 — 重生成中间 assistant 消息导致错序（中，✅ 本次已修）

- **位置**：`regenerateAssistantMessage`（main.js L4628-4649）。
- **根因**：函数仅 `splice` 掉目标 assistant 那一条，其后的消息保持不动；随后 `askChatTurn` 把新回复**追加到会话末尾**。`extractHistory` 也会把目标之后的消息一并作为上下文发给模型。
- **现象**：对**非最后一条** assistant 消息点"重生成"时，新回复出现在会话末尾而非原位，且模型看到了"未来"的对话上下文——顺序错乱 / 重复。
- **说明**：`buildMessageToolbar` 对**每条** assistant 消息都渲染重生成按钮（L4450-4455），因此该边界可被用户触发。
- **建议修复**：重生成前先 `rollbackMessagesAfter` 到对应 user 回合（对齐编辑语义），或明确仅允许对最后一条 assistant 重生成。
- **修复（本次）**：采纳前者——重生成先 `rollbackMessagesAfter(userMessageId)` 回退到 user 回合（连同服务端 `discardFollowing` 清理），新回复不再错序追加到末尾。与 BUG-P01-02 同一处改动。

## 备注（非阻断）

- **NOTE-P01-05 — 过时注释（低，✅ 本次已修）**：`main.js` 曾声称服务端保存"insert-only and has no update path"，但 `sessions.js` 现已改为 `onConflictDoUpdate`。**修复**：注释已改写为准确描述 upsert 语义，并说明过滤 streaming 占位行的真实理由（避免持久化半渲染内容 / 无谓写入）。
- **NOTE-P01-06 — 编辑保存时序竞态（低，✅ 本次已修）**：`PATCH(discardFollowing=true)`（删除 `createdAt >= user 回合` 的 assistant 行）与随后保存的新回复并发，删除迟到可能误删新回复。**修复**：`editUserMessage` 与 `regenerateAssistantMessage` 均改为 `patchPromise.then(askChatTurn)`——先中止在途流，待 PATCH（含失败 `.catch` 兜底）落定后再发起新回合，保存必晚于删除；PATCH 通常亚秒级，相对模型延迟无感。
- **A4 复核（编辑离线一致性，待后续）**：编辑时 PATCH 失败仅弹 toast，本地已裁剪但服务端仍留旧行，硬刷新会复现旧回复。属乐观离线设计，缺失败重试队列，登记为后续增强（P2 迭代）。
