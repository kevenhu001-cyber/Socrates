# 0017：聊天执行领取与定时任务租约

日期：2026-10-16。状态：已实现，生产验收待执行。

## 问题

唯一的 Chat Turn 记录不代表模型只执行一次。重复流式请求原先仍能分别进入 pipeline。
调度器先推进 nextRunAt 再调用模型，进程在这两步之间退出会漏掉本轮任务；进程内锁也不能协调多个 API 实例与手动运行。

## 决策

聊天在任何模型准备或工具执行前原子地将 queued 改为 running。重复执行请求收到含 CONFLICT / 409 的 SSE 错误和 turn_bound（HTTP 已提交时仍为 200），改用持久化事件流重连。clientTurnId 不能跨会话重用。执行每 20 秒续心跳，超过 120 秒未更新的 running 记录在恢复扫描中转为 interrupted；每 30 秒扫描。中断记录不能被迟到的终态写入改回 completed，也不能自动重新执行，以免重放工具副作用。

调度器使用新增的 scheduled_task_leases 表。每个任务至多有一个当前租约，执行 ID、随机 owner token、数据库时间过期点、尝试次数以及执行时的 agentKind 均持久化。

- 所有领取和完成事务先锁任务行，再访问租约；事务中不调用模型。
- 90 秒租约每 20 秒续期；失去续期或关闭调度器时取消上游请求。
- nextRunAt 在执行期间保持不变；结果消息、runCount、下一次运行时间和租约终态在一个事务中提交。
- 普通 LLM 任务在过期后保留 executionId 并换 owner token；消息 clientId 由 executionId 派生。旧 owner 不能续期或提交结果。
- 工作区 Agent 或执行类型已变化的过期任务记为 uncertain 并暂停，不自动重放未知副作用。需要查看 agent run 历史后显式手动重试。
- 保留执行过程中用户设置的暂停状态和下次运行时间。手动运行周期任务不移动正常的下一次执行时间。
- 租约不进入公开任务 JSON。定时轮询通过过期租约发现待恢复任务，并跳过仍被其他实例持有的任务。

普通推理请求在进程崩溃后仍可能再次调用提供商并产生重复计费。这一机制保证数据库结果的原子提交与旧 owner 写入拦截，不宣称提供商或外部系统 exactly-once。
先后发起的手动运行属于不同执行；通用 HTTP 幂等跨实例持久化仍是后续工作。

## 迁移与回滚

`0041_scheduled_task_leases.sql` 仅新增表、外键和索引，支持重复运行；快照和 journal 同步更新。部署 schema 验证门禁增加该表。旧 schema 的运行进程不受添加表影响。

旧调度器不认识租约，不能与新执行器混合运行。上线时先迁移，再停止/排空旧版本的自动及手动执行请求，切换所有相关进程，最后开启新调度器。新版本可设置 `SCHEDULER_ENABLED=0` 暂停自动轮询，但该变量不关闭手动运行接口。现有单进程 deploy.sh 的停旧进程再切换流程满足版本不重叠要求；多实例必须协调切换。

回滚时先停新执行器，核对 running/uncertain 租约及对应 Agent 历史，再恢复旧执行器。保留新增表；不要在线 DROP TABLE。旧版本会忽略租约，因此不得依赖它继续维护新版本的并发保证。
旧版本已经丢失、且没有租约记录的一次性任务无法由新表重建，需要人工核对，不能批量自动重放。

## 验证

使用独立 PG16 与本机模拟模型，不调用真实提供商。覆盖独立进程并发领取、领取后进程退出、心跳续期及过期拒绝、接管后迟到提交、手动/自动运行冲突、一次性任务恢复、周期任务与手动运行时间、用户中途暂停、Agent 不确定结果处理，以及真实 HTTP 并发聊天只调用一次模型。另验证迁移可重复执行与元数据无漂移。
