# ADR 0018 — 数据库写入与幂等回执原子提交

日期：2026-10-16。状态：代码已实现，临时库验证；生产未应用。

跨实例重试不能依赖进程内 Map。只是在业务写入后补存回执，仍会在“业务提交成功、回执尚未写入”时重复创建。本次选取完全由 PostgreSQL 事务覆盖的四个操作：创建项目、创建提示词、创建定时任务、替换会话标签。执行任务、模型调用、文件上传和外部工具副作用不使用该抽象。

## 决策

- `runDurableJsonWrite` 的 callback 只能通过提供的 tx 执行数据库操作；禁止网络请求、文件写入、发送 HTTP 响应或通过独立连接写业务记录。
- `idempotency_receipts` 与业务写入在一个事务提交。提交前崩溃全部回滚，提交后响应丢失则重放保存的状态码与 JSON 字节。没有键时也使用事务，但不保留回执。数据库故障不降级为不受保护的写入。
- 对“用户 ID、凭证 SHA-256、操作版本/资源 ID、请求键”生成 SHA-256 主键。操作版本使 `/api` 与 `/api/v2` 共用逻辑作用域；会话 UUID 大小写统一。原始凭证与请求键不落库。换凭证产生新作用域，客户端应在相同凭证下重试。
- PostgreSQL 事务级非阻塞 advisory lock 限制同键执行；竞争者返回 `409 IDEMPOTENCY_IN_PROGRESS` 与 `Retry-After: 1`。64 位锁哈希碰撞只会暂时使无关请求繁忙；完整键哈希及指纹负责回执匹配。锁不依赖应用计时器，连接退出自动释放。
- 请求体指纹按 JSON 对象键排序，数组顺序保留。有效回执与不同指纹冲突返回 `409 IDEMPOTENCY_CONFLICT`。运行中竞争者还未读取未提交指纹，因此统一返回 IN_PROGRESS；待完成后才判断冲突。
- 成功回执从提交事务接近结束时的数据库时间起有效 24 小时，过期后允许重新执行。单响应最多保存 256 KiB；超出时仅保存完成标记，重试得到 `409 IDEMPOTENCY_RESULT_UNAVAILABLE`，不能再次执行。TTL 不因回放延长。失败事务不留回执。
- 四个操作从全局进程内缓存中排除，经过 `requireAuth` 和各路由既有权限检查后才查询回执。没有扩大现有 scope 词汇或修改其余路由的授权模型。浏览器认证仍遵守原有 30 秒缓存失效窗口；本次没有实现跨实例即时撤销。
- 回放是历史响应，不代表资源当前状态；资源被编辑或删除后仍回放原结果。客户端需要当前状态时使用读取接口。会话标签的实际写入额外锁定所属会话，使删除旧关联和插入新关联串行提交。
- 每小时清理过期回执，用户删除通过 FK 级联清理。过期时间和 user_id 有索引。回执会保存业务响应内容，与应用数据库同级保护；没有保存完整请求体。

## 发布与回滚

`0042_idempotency_receipts.sql` 为增量建表，包含快照和 journal，可重复应用；部署 schema 门禁要求新表存在。旧代码能容忍额外表，但不会读取回执，不能保证混合版本间的同键互斥。先迁移，再排空旧写入者并整体切换流量；切换前的进程内缓存无法转换为持久回执，需要避免跨切换重复提交。回滚时保留表，停止/排空新写入者，并确认客户端重试策略；启动旧代码意味着主动放弃这四个操作的持久化重试保证。不要在回滚时删除有效回执。

## 验证与剩余边界

独立 Node 进程共享临时 PG16，覆盖并发唯一提交、提交前 SIGKILL 回滚与接管、提交后 SIGKILL 再启动重放。真实 Express 路由覆盖四个操作、大小写/尾斜杠、不同请求体、不同用户、无键、非法键、失效凭证及权限收缩。错误回滚、对象规范化、大响应完成标记、TTL 与凭证隔离也有回归。

其他路由继续使用进程内缓存；没有声称所有 API 都支持持久幂等，也没有实现外部副作用的 exactly-once。24 小时以后或换凭证后的请求需要业务唯一键另行保护。数据库总回执容量尚无硬配额；需在后续补存储指标、按账号容量和保留策略，不能套用进程内缓存的 32 MiB 总上限。没有进行生产部署、生产迁移或压力验收。
