# 提示词体系梳理与优化

本次目标是使实质性回答具有充分的解释深度、清楚的逻辑和启发性，以连贯段落组织正文，减少机械使用冒号、破折号和大量分点，同时保留用户明确指定的格式和必要的结构化交互。

## 方法与范围

依据 OpenAI 官方[提示词工程指南](https://developers.openai.com/api/docs/guides/prompt-engineering)中关于区分身份、指令、示例与上下文，以及提供明确行为示例的指导，审查实际发送给模型的组合指令。评测设计参考官方[评测最佳实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices)，分别验证代码装配和生成质量，避免把提示词关键词测试当作模型效果证明。这些通用方法用于本项目的多模型链路，不代表所有提供商具有相同的指令遵循能力。

审查覆盖普通聊天、教学角色、六种学习模式、前端阶段指令、Universal App 对应阶段指令、原生 Android 教学提示词、语气预设、代码执行附录以及旧会话快照的规则刷新。考试生成、标题生成、摘要、诊断 JSON 等专用任务仍以各自输出契约为准，不应强制改成长篇散文。

## 实际规则归属

`server/src/lib/chatPolicy.ts` 拥有服务端工具及信任边界、学习交互协议和最终表达默认值。`packages/core/src/learningUi.js` 拥有原生学习节点字段契约。`prompts/beagle.md` 只补充内置提供商身份，不向自定义提供商泄漏身份，也不复制全局表达规则。

`prompts/teacher-mode.md` 负责教学方法和 KaTeX 兼容细节。`prompts/learning-modes.md` 负责用户本轮选择的学习活动。前端 `systemPrompts.ts` 和 `prompts/socratic.ts` 只补充角色与任务倾向；`socraticDirectives.ts`、`tutor/flow.ts` 及 `packages/ui/src/tutor.ts` 提供当前课程阶段和学习状态。语气预设只调整措辞和人际距离。

普通聊天通过 `prepareChatRequest` 装配服务端边界和初始化上下文，经 `resolveSessionPromptOrAssemble` 保存稳定快照。每轮另加学习模式、客户端课程状态和检索证据。内置代理也使用同一套服务端规则，提供商身份按请求加入。工具路由及预算由后续执行链路依据实际工具集合补充，不能假定快照里有某个工具就始终可用。

旧会话不重新保存身份、记忆或初始化日期。已有 `insertResponseTypography` 刷新出口同时刷新最终表达规则；本次也覆盖缺少最终标记的旧提示词。保存的旧角色可能仍包含历史指导，但当前最终规则明确使历史 XML 示例失去新输出协议的效力。教学角色正文的精简适用于新装配的会话；没有对数据库里的历史快照做整段改写。

## 发现及处理

最明显的协议冲突是服务端要求原生 JSON 学习节点，而前端共享指导、教学角色和学习模式仍示范 XML 卡片。现在移除这些主动生成 XML 的指导，统一引用服务端协议，保留旧消息解析器以读取历史内容。无工具时退回自然语言或 Markdown。代码执行附录也移除了把静态图形包装成 `Visualization(...)` 的过时建议，改为原生 JSON visualization 节点。

教学控制存在两类冲突。一类是动机阶段要求先建立直觉、不定义概念，而基础锚点和课程上下文要求立即从正式定义开始。现在把基础要求解释为先建立必要基础，在 motivate 阶段用直觉，在 define 阶段定义。另一类是基础锚点要求空白基础至少给三个例子，而阶段规则限制一个或两个。现在按理解程度调整先修解释、步幅和支架，不再强制例子配额。两个客户端采用同样的措辞，并用组合回归检查一致性。

当前学习模式优先于冲突的客户端阶段计划，用户明确要求解释或求解时可以改变默认活动。阶段指令不能自称覆盖所有格式和长度规则。知识联系模式也不再把每个关系限制为一句话，允许充分解释真实联系及其成立原因。

请求链路检查还发现 Universal App 和原生 Android 的教学指导缺少服务端识别标记，会被归入不可信背景数据。现在教学指导带有 `[Current turn instructions]`，每轮进入课程上下文而不写入稳定快照。Universal App 的普通聊天语气带有 `[Assistant mode instructions]`，按已有服务端分类规则作为从属的应用指导。没有放宽服务端对任意客户端 system 内容的分类标准。原生 Android 同时去掉了固定简短和每次必须提问的要求，明确允许用户直接要求解释或完整解答。

上一轮补充的详细表达指导与全局正文规则有所重复，本次让全局规则引用最终表达默认值，避免维护两份深度、段落和列表规则。最终规则明确说明风格不能覆盖工具、真实性和不可信数据边界，替换了“覆盖所有上文规则”的过强声明。默认语气的 “reasons out loud” 改为提供可核验依据；高效语气不再暗示用户必须再次要求才能得到充分解释。

## 输出质量要求

实质性问题先回答当前问题或交付用户要求的结果，再依照问题需要展开原因、机制、例子、实际意义和条件。每个段落发展一个主要观点，明确段落之间的因果或依赖关系。启发性体现为帮助用户理解为什么成立、在哪些条件下成立，以及如何迁移到新情境，而不是增加反问或强迫测验。

用一个简短的中文示例展示如何在段落中连接直觉、机制、前提和实际意义，并明确它只是风格片段，不是所有回答都要套用的模板。事实性短问仍可简答；用户要求编号步骤、表格、合法 JSON 或原样引文时遵从对应格式。冒号和破折号是表达偏好，不是字符替换规则；代码、数学、URL、精确引文和结构化语法必须保持有效。

## 可重复评测

评测数据在 `server/test/fixtures/response-quality.json`，包含 16 个场景及各自判据，覆盖长解释、误区纠正、直接求解、上下文延续、简答、编号步骤、JSON、精确引文、英文、原生测验、无工具退化、模式与阶段冲突、不可信指令和工具失败。它是待执行的生成质量评测集，不是模型已通过的评分报告。

测试时使用同一提供商和具体模型、相同采样参数、相同会话历史和工具集合，对基线与候选提示词各生成至少三次。基线使用本次修改前的独立测试构建或预先保存的基线输出，不为此切换或清理当前工作区。为每个样例创建独立会话，避免旧快照混入对比；旧会话更新效果单独测试。工具失败场景通过模拟结果注入，不实际制造外部副作用。保存完整请求的规则版本、模型版本、响应和工具记录，敏感上下文脱敏后才进入评测材料。

人工或模型裁判盲评并随机打乱先后顺序。按任务完成度、正确性与证据、解释深度与迁移价值、逻辑及连续性、表达自然度、格式适配六项分别给 0 到 4 分，并引用回答中的具体证据。0 表示违背要求，2 表示基本可用但存在明显缺口，4 表示充分完成且没有实质缺陷。裁判不得因为回答更长或标点更少就自动给高分。

任何编造已完成的工具动作、泄漏未作答测验答案、无视明确格式、破坏 JSON/代码/原样引文或把不可信内容当命令的情况，单独记为硬失败，不能用文风得分抵消。冒号及破折号密度、列表占比、长度和延迟只作为辅助信号，统计时排除代码和引文，结合任务类型判断，不设所有任务通用的字符阈值。

本轮验收建议是候选在解释深度、逻辑和自然表达三项的平均得分优于基线，其他三项平均得分不下降，并且没有硬失败。逐例查看失败和打平的原因，不能只看平均数。样本规模不足以声称统计显著，也不能从一个模型推断其他模型必然改善。

## 验证与发布边界

组合回归检查 Chat/Tutor 拼装后的指令、六种学习模式与角色协议的一致性、Web/Universal App 的阶段措辞一致性，以及旧快照刷新和幂等性。原有原生学习节点测试负责检查字段校验与渲染契约，前端冒号/破折号偏好不通过后处理改写模型正文。

本次不修改 API 字段或数据库结构，不需要迁移。后端 TypeScript 常量变更需要按正常流程重新构建并发布服务端；不能因为 Markdown 加载支持热更新，就认为这次全部改动无需发布。回滚时恢复本次源码和提示词文件并重新构建，已有快照会在请求出口使用回滚版本的表达规则。发布操作和真实模型生成评测未包含在本地静态及模拟验证中。

本地验证结果如下。

- 服务端类型检查通过，相关测试累计覆盖 130 个不同用例，包含当前提示词组合及快照回归。
- 前端完整 lint 和生产构建通过，包体积门禁通过。lint 输出一处未改动组件 `TurnActivitySurface.tsx` 的复杂度警告，无错误。
- 前端 46 个相关单元用例、共享 UI 13 个用例、设置包 3 个用例通过。
- SPA 聊天发送、停止重发、流式渲染、消息列表与教学会话的 36 项 Playwright 回归通过。
- Universal App 类型检查、Web 导出和桌面/手机视口的 2 项教学回归通过，验证发出的教学指导携带本轮指令标记。
- Universal App 首次导出遇到共享 TS 模块 `./physicsModels.js` 解析失败。Metro 增加仅对不存在的相对 `.js` 路径查找 `.ts`/`.tsx` 源码的处理，保留真实 JS 和包导入。对应解析回归通过，重新导出及上述浏览器测试通过。
- 原生 Android 的 `assembleDebug testDebugUnitTest lintDebug` 未完成。正常联网解析长时间无进展，离线运行明确报告多项 Gradle 插件传递依赖没有缓存，使用环境代理进行有时限重试也在 90 秒内未完成。尚未验证 APK、Kotlin 单测、Android lint 或设备测试，应在具备完整依赖的 CI/开发环境补跑。没有用静态检查代替这些构建结论。
- 16 个真实模型生成质量场景已准备，尚未调用真实模型进行基线对比，不能据此声称质量得分已提高。
