# 性能与 UI 整理：第一轮（2026-10-15）

本轮范围是当前 `frontend/` SPA 的发送反馈、首页快捷入口、首轮重试和首页 CSS 归属。没有修改冻结客户端、服务端 API、数据库或部署配置。

## 已修复

| 问题 | 修改及验证方式 |
| --- | --- |
| 发送后附件和焦点处理等待流式模块加载；等待期间新添加的附件可能被随后执行的清理删除 | 普通聊天及首页首轮发送都在异步加载之前清理已提交的草稿和附件。浏览器测试人为阻塞流式模块入口，检查用户消息已出现、草稿已清空、下一轮附件在解除阻塞后仍保留。 |
| 流式模块加载与附件准备串行执行 | 两种发送入口均并行启动，首次重试复用该轮的内容 Promise。网络发送仍等待附件准备完成；首轮保留原有会话保存顺序。 |
| 首条预建回复的重试回调只输出日志 | 回调重新发送原始文本及该轮附件，不读取后续草稿。浏览器测试直接调用传给真实占位回复的回调，并检查第二次请求内容。 |
| React 错误行“重试”点击没有请求 | `liveTurn` 校验误读了控制器的 `clientId` 字段；控制器实际提供 `getClientId()`。改用公共访问器，同时保留旧对象字段兼容；新增单元测试覆盖身份匹配、拒绝其他消息和旧对象兼容。 |
| 首页“上传文件”只打开工具菜单 | 直接调用现有附件选择器，保持文件类型、上传和附件芯片的统一流程。测试使用真实 filechooser 事件上传文本文件。 |
| 手机端已隐藏的首页快捷入口仍有两组旧布局声明 | 从 `restore/mobile-parity.css` 删除 15 条失效规则；桌面入口仍由 `polish/home.css` 管理，手机隐藏状态由 `polish/mobile-shell.css` 管理。扩展现有 CSS 归属检查，禁止兼容层重新加入这些选择器。 |

CSS 债务基线只向下更新，不增加 `!important` 或新的覆盖层。`themes.css` 的唯一、最后导入约定保持不变。

## 第二轮补充（2026-10-15）

第一轮保留的手机长会话重试定位失败现已修复。浏览器探针捕获到 React 提交期间的 `NotFoundError`：`streamRetry.prepareViewport` 在更新状态后，又直接删除 React 管理的消息节点。现在 React 行只由状态驱动移除，旧 DOM 路径保留原有清理；既有 `chat-send` 重试位置断言恢复通过，没有放宽断言。

同时修复并整理了以下问题：

- 旧 `message.html` 中的错误/重试块与 React 的终态控件重复出现。React 终态现在只保留一个 Retry/Resend 控件，兼容 HTML 的正文保留。
- 聊天链接预读取增加 2.5 秒预算；响应头、正文或传输停滞均不会无限阻塞模型请求。超时通过原有上下文失败标记降级，不能据此声称已读取网页。研究流程使用 10 秒预算，允许服务端原有的 8 秒页面读取窗口。
- 回复控制器在读取页面之前创建，链接准备阶段接入 Stop、后发消息和会话重置取消；取消后的旧准备任务不会再发出模型请求。
- 错误/重发状态的五条旧规则从 `legacy/10-tutor-scaffolds.css` 移至 `features/thinking-activity.css`，使用统一主题、圆角和字号令牌。Retry 桌面最小 32px，手机触控最小 44px；扩展现有归属检查，禁止兼容层重新争夺这些状态的样式。

验证：最终生产构建与完整 lint 通过；`streamRetryViewport`、`streamRetryProperties`、`webLinks`、`toolRunModel` 共 66 项单元测试通过。七组浏览器规格覆盖 35 个场景：初次运行 34 项通过；新增会话重置测试因未操作现有确认弹窗而超时，补齐真实确认操作后该项单独复跑通过。覆盖慢链接超时、Stop、新消息替换、会话重置、错误重试、附件、流式滚动及消息列表兼容。
