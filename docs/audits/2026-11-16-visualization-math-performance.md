# 可视化公式与长对话渲染检查

## 原因与修复

`frontend/src/render/markdownMath.ts` 原先用大小写和字母数判定紧凑公式，拒绝 `$ct$`、`$xy$` 等连续小写字母。这个判定由正文、流式正文和可视化标签共享，因此修改提示词无法修复已经生成的内容。现在允许所有符合紧凑公式字符集的标识符；闭合公式不再按英文单词猜测。货币边界、段落边界和代码片段的保护仍独立生效。开放的全大写货币前缀仍等待结束符。

服务端已有统一的“显示公式使用 LaTeX，执行表达式与数值使用机器语法”约束，两者适用字段不同，并不矛盾。本次只补上 ct、xy、dt 这些简单符号的明确例子，没有再叠加一段重复提示词。运行时代码承担确定性的渲染保证。

浏览器还确认了重复安装：`visualization.ts` 在卡片上安装公式监听器，原生 SVG、Plotly 和 Mermaid 又在内部 stage 上安装一套。两套观察器各自维护覆盖层，会生成重复公式，并观察到对方的 DOM 更新。现在只保留卡片级唯一所有者，渲染器切换和主题重绘由同一观察器接管。

`frontend/src/render/visualizationMath.ts` 原先在宿主的任意相关属性或子树变化后遍历整图、删除全部公式覆盖层，再调用 KaTeX 和 `getBBox` 重建。动态图形和分组变换也触发这条路径。现在收集发生变化的文字及子树，保持其他公式的 DOM；形状属性和共同祖先的平移不触发重排；需要改变位置时复用排版结果，每张图缓存最多 256 个字符串。离开可视区域的图表延迟公式工作，接近视口再处理，销毁时取消帧与观察器。

`frontend/src/render/visualizationSandboxMath.ts` 原先在任意文本变化后遍历整个 iframe 文档。现在只遍历新增或变化的子树，并跳过已渲染公式。原先 200 个在途请求的上限还会直接跳过后续公式，且不保证再次扫描；现在保留未处理子树，在响应释放名额后继续处理。

`frontend/src/react/message-list/MessageList.tsx` 把滚动和 resize 引起的滚动边缘计算合并到每帧一次，仅在跨越顶部边界时修改 body 属性，避免滚动中重复写入相同属性。

`frontend/src/chat/turnAnchor.ts` 的发送定位锁只在尺寸变化时检查用户是否滚离底部。若滚动后没有 resize，`turnViewportOwner=turn` 会遗留，历史窗口拒绝继续挂载旧消息，表现为滚到一半不能继续。现在持有定位锁时订阅状态变化，用户滚动意图立即释放所有权和观察器；释放时取消订阅。回归测试验证无 resize 也能释放，浏览器验证可以滚到真正的首条消息。

四倍 CPU 降速的进一步采样发现，长对话的重复同步布局也来自 `aboveViewportResize.ts`：每次提交后都读取 scrollHeight，再记住一次阅读锚点。现在通过 MutationObserver 与 takeRecords 检查 DOM 变化位置；只有阅读块之前、内部或其祖先发生变化时才恢复并重新测量锚点。严格位于阅读块之后的流式更新无需做这次工作。阅读锚点优先选择已经稳定的 tool-run-prose 段落，而非包含整篇回答的容器；没有这种结构的历史/用户消息使用原有回退选择器。首次挂载、滚动、锚点被替换和不支持 MutationObserver 的环境保留原来的测量路径。新增单测覆盖前后节点、块内部、祖先样式、未变化和已删除节点。性能测试还支持 `PERF_PROFILE=1`，通过 Playwright 附件导出 CDP CPU profile，方便以后定位同类开销。

截图复查还发现原生 SVG 的默认黑色填充在深色背景上不可见。未声明根 fill 的 SVG 现在用 currentColor 继承卡片文字颜色；显式填色继续由作者决定。浏览器回归不仅检查 KaTeX DOM，也检查默认标签颜色，避免“渲染了但看不见”的假通过。

## 与参考实现的比较

本地只读参考 `chat-demo/src/components/markdown/MathFormula.tsx` 用 memo 和 useMemo 保持未变化公式的结果，流式不完整公式保留上次成功结果；`useThrottleMarkdownRender.ts` 根据提交耗时节流。它展示了应避免无意义重复排版的做法，但不能据此断言整个参考客户端在所有负载下都流畅。

Socrates 已有历史消息挂载窗口、settled 段落缓存、消息 memo 和按可见性暂停的原生演示/3D 循环。本次没有用整体降帧替代它们，而是修复绕过这些机制的可视化监听器。大量历史消息与一个超长回答是两种负载，浏览器性能用例同时覆盖两者。

## 回归覆盖

- 公式：ct、xy、dt、abc、xMax，正文流式/完成态、图表、沙箱及代码/货币边界；原生 SVG 断言只有一个公式覆盖层。
- 增量渲染：20 次形状与父分组移动保持公式节点；文字几何变化复用排版；修改一个公式不重建另一个；销毁释放覆盖层。
- 队列：220 个沙箱公式全部完成渲染。
- 长对话：现有 performance-streaming 用例，500 条历史消息与 260 个已完成段落，普通和四倍 CPU 降速，流式期间输入、段落复用和消息挂载数量。

没有数据库迁移或 API 线格式变更；没有修改只读 chat-demo。测试负载不能保证任意生成的 JS、任意数据规模和所有设备均恒定帧率。
