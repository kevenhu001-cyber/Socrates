# Socrates agent guide

## Task entrypoints and ownership

- `frontend/` owns the Vite SPA, tutor/chat flows, exam UI, visualization cards, and Playwright coverage. Start with `frontend/src/main.js`, then follow extracted modules under `frontend/src/`. Verify with `npm run lint`, `npm run test:unit`, `npm run build`, and the relevant Playwright specs.
- `server/` owns Express APIs, Drizzle/PostgreSQL persistence, LLM/tool execution, authentication, and the Python sandbox. The source entry is `server/src/index.runtime.ts`; `server/src/index.js` is only a compatibility shim that imports `../dist/index.runtime.js` for existing systemd units. Verify with `npm run typecheck` and `npm test`.
  - `npm test` runs `scripts/run-tests.mjs`, which spawns one Node process per file with `--import dotenv/config`. DB-backed suites skip unless `DATABASE_URL` is set.
- `mobile/` owns the Expo/React Native client (`socrates-mobile`). It consumes `@socrates/core` and `@socrates/contracts` from `packages/`. Verify with `npm run typecheck` and `npm test` (Jest). Android is produced via `expo run:android` / `export:android` — the `android/` tree is generated by `expo prebuild`, so there is no checked-in Gradle wrapper to run.
- `packages/` owns the shared TypeScript packages (`@socrates/core`, `@socrates/contracts`) used by `mobile/`. Both are published by path, not by npm.
- `site/` is a separate static marketing/docs site deployed to its own vhost. It is not part of the SPA build.
- `tools-rust/` owns the Rust crates (`protocol`, `format`, `stream`, `fetch`, `wasm`). The WASM output is consumed by the frontend via `npm run build:wasm`.
- `open-connector/` is a vendored fork of `oomol-lab/OpenConnector` (Apache-2.0). **Status as of 2026-09-20**: 10 files in `server/src/` (services + routes + tests) and 10 files in `frontend/src/` (workspace/* + connector-icons) consume the integration surface (`openConnectorChatTools`, `openConnectorCatalog`, `openConnectorSidecar`, `openConnectorCloudAuth`, `openConnectorAppInventory`, executor/registry wiring). Changes below `open-connector/` therefore go through review of the dependent code in `server/` and `frontend/`. See `docs/audits/2026-09-20-structural-review.md` (F-003) and `docs/adr/0003-structural-debt-categories.md`.
- `capacitor/` is a **legacy WebView wrapper**, originally said to be superseded by `mobile/`. **Status as of 2026-09-20**: dormant in `server/` (no import) but **still referenced** by `frontend/src/main.js`, `frontend/index.html`, `frontend/src/native/capacitorBridge.js`, and built by `.github/workflows/build-capacitor-apk.yml` (debug APK artifact `socrates-capacitor-debug-*`). Treat it as frozen unless explicitly re-opened by a future PR — F-007 in `docs/audits/2026-09-20-structural-review.md`.

## Boundaries and risk routes

- Do not commit generated `dist/`, test reports, secrets, or deployment state.
- Treat `frontend/src/main.js` (actual **931 lines / ~47 KB as of 2026-09-20** — historical descriptions referring to 10k+ lines are stale and reflect a pre-split state), `server/src/index.runtime.ts`, auth, migrations, and `deploy.sh` as high-churn or high-impact surfaces. Prefer extracted modules and add focused regression coverage. Larger companion files that also warrant the same caution: `frontend/src/styles/legacy/` (the old `styles.css` monolith, split 2026-09-23 into 17 order-sensitive slices; cascade order is defined by `styles/index.css` → `legacy/index.css`), `frontend/src/i18n.js` (2 117 lines), `frontend/src/chat/streamingTurn.js`, `frontend/src/sidebar/nav.js`, `frontend/src/render/{markdown.ts,viz.js}`.
- `deploy.sh` must remain single-writer, preserve `dist.previous`, and restore the previous backend after a failed restart or health gate. If changing its swap/rollback flow, test the lock, candidate cleanup, and error trap paths.
- `.github/workflows/ci.yml` is the frontend/server merge gate. Keep type checks, build, unit tests, and frontend Playwright smoke tests intact; preserve concurrency cancellation and failure artifacts. **CI coverage as of 2026-09-20** (a stale "untouched" list previously lived here): `ci.yml` (131 lines) is the gate; `mobile-apk.yml` (139 lines) and `build-apk.yml` (804 lines) cover `mobile/`; `build-capacitor-apk.yml` (92 lines) covers `capacitor/`; `release-clients.yml` (135 lines) coordinates multi-client releases; `agent-tooling-ci.yml` (156 lines) covers `tools-rust/`-related harnesses; `server-ci.yml` (55 lines) covers `server/`; `build-windows.yml` (55 lines) covers Windows packaging; `android-device-smoke.yml` (144 lines) runs device-side smoke. `site/`, `packages/`, and `open-connector/` still lack dedicated CI; work to scope each workflow by `paths:` is tracked in F-004 and `docs/adr/0009-ci-workflow-paths.md` (P1).
- **Brand assets — favicon is locked to `logo.png`.** `frontend/public/favicon.png` and `site/favicon.png` must stay byte-identical to their respective `logo.png` siblings (currently 2077 bytes each). Do not replace either favicon with a tray variant, an emoji, a service icon, or any auto-generated image. If the logo itself is updated, re-copy `logo.png` over `favicon.png` in the same directory; both files move together.
- **`allowScripts` is an allow-list, not a switch.** `server/package.json` and `frontend/package.json` declare `allowScripts: { "esbuild": true }`. Until 2026-09-25 both declared `{ "*": true }`, i.e. every one of 1,000+ transitive packages could run arbitrary code during `npm install`. Only esbuild genuinely needs a script (its postinstall fetches the platform binary; without it `vite build` fails). Do not widen this back to `"*"`. If a new dependency needs a script, add it by name and say why in the commit. `mobile/` deliberately has no `allowScripts` field: its `detox` and `dtrace-provider` scripts are needed by the Android toolchain, and narrowing it cannot be verified here (no Android SDK) — tighten it in a change that can run `expo prebuild`.
- **CI installs with `--ignore-scripts` where it can.** `server-ci.yml` and the Security workflow's audit jobs use it because a typecheck or an advisory lookup never needs a package's install hook. The main `ci.yml` jobs do not, because they build.

## Next checks

- Frontend behavior/UI: build first, then run a focused Playwright spec; inspect a screenshot for visual work.
- Server or schema: run typecheck and focused tests; document migration/rollback implications.
- Cross-client API changes: update the OpenAPI description and check `mobile/` compatibility.
- Deployment changes: use a non-production dry-run environment or shell-level validation before operating on web roots or services.

## Incremental testing (required)

Do not run the full `test:unit` / Playwright suites for every change. Tests are slow
(unit ≈2 min, full Playwright much longer), so map the diff to tests and run only those.

1. Find the change set: `git status --short` + `git diff --name-only HEAD` (or diff
   against the last verified commit you recorded).
2. Map changed files to specs:
   - `frontend/src/styles*` (tokens/themes/shell CSS) → `e2e/landing-light-visual`,
     `e2e/chat-light-palette`, `e2e/theme-system`, `e2e/chat-workbench`,
     `e2e/home-customization`.
   - `frontend/src/ui/sidebarResize.js`, sidebar chrome/nav → `e2e/sidebar-resize`,
     `e2e/sidebar-compat`, `e2e/sidebar-nav`.
   - Composer (`react/composer-input`, `ui/composerTools`, `#chatInputWrap`) →
     `e2e/composer-*`, `e2e/chat-workbench`, `e2e/repro-input-overlap`.
   - `frontend/src/chat/*` / `render/*` → `e2e/chat-send`, `e2e/chat-stop-resend`,
     `e2e/streaming-render`, `e2e/message-list-compat`, plus `test/<module>.test.mjs`.
   - New modules with no matching spec: run only the smallest relevant unit file
     (`node --experimental-strip-types --test test/<file>.test.mjs`) and add a focused
     spec instead of relying on the full suite.
3. Run a subset, e.g.:
   `npx playwright test --config=playwright.config.mjs e2e/<spec>.spec.mjs --workers=1`
4. If an existing spec fails, rebuild `git stash`-clean HEAD (or inspect the traces)
   to confirm it is pre-existing before attributing it to the change.
